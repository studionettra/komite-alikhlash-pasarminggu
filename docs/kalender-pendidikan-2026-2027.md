## Ringkasan Struktur Data (untuk referensi implementasi)

Jadwal renang sudah menyatu dengan tabel Kegiatan di bulan yang bersangkutan (September, Oktober, November) — tidak dipisah jadi entitas/tabel sendiri, agar hanya ada satu sumber data (satu seeder) yang perlu dijaga.

Setiap bulan memiliki dua kelompok data yang bisa dipetakan menjadi struktur JSON/props React:

```
{
  bulan: "September",
  tahun: 2026,
  hari_efektif: "22 hari",
  kegiatan: [
    {
      tanggal: "16",
      kegiatan: "Kegiatan Renang (Rabu)",
      keterangan: "Kelompok A2 + B + BL2 (Pj. Bu Caca)"
    },
    ...
  ],
  program_pembelajaran: [
    { minggu: "I", topik: "...", tanggal: "1 - 6", sub_topik: "...", keterangan: "Sesuai Silabus" },
    ...
  ]
}
```

Catatan field `hari_efektif`: untuk bulan yang tidak memiliki jumlah HE pasti (Oktober, Januari), field ini diisi `"-"`. Untuk Mei dan Juni, field ini diisi teks deskriptif karena bulan tersebut didominasi kegiatan evaluasi/pentas, bukan hari KBM reguler penuh.

Struktur ini bisa langsung dipakai sebagai seed data tunggal (misal `database/seeders/KalenderPendidikanSeeder.php`) atau sebagai props statis yang dikirim dari controller Inertia ke komponen React halaman kalender akademik — satu sumber kebenaran untuk orang tua, tidak ada data ganda antara kalender akademik dan jadwal renang.
